# 子比兼容与完整下载页双模式（v3.1.0）

九流 WP 助手针对子比（Zibll）的边界原则：不修改主题文件、不修改正版授权信息、不覆盖原生 AJAX/REST 请求处理器、不替代订单、登录、支付业务逻辑。

## 哪些是纯展示扩展

- 页面美化、AI 摘要、预加载及下载页皮肤依赖 WordPress 通用页面挂载点，输出只属于 WP 助手自己的 CSS/JS/HTML。
- 开屏预加载的“点击跳过”只监听自身遮罩，不再安装全局 900ms 点击阻断，防止遮罩结束时吞掉子比登录或支付弹窗操作。
- 下载页新增“**完整经典模板**”与“**子比原生兼容皮肤**”双模式。经典模式恢复 v3.0.6 原来的完整六款页面（默认），在 WordPress 正常 template_include 阶段选择插件模板，不提前 include/exit；子比原生模式只加 CSS、客服组件，由子比负责执行 `zibpay_get_down_html()`、渲染支付状态、文件按钮、提取码及订单数据。
- 客服／群组仅为额外的自有元素，使用站长配置，默认空，不修改子比表单、节点、事件处理器或 XHR。
- 经典模式保留原版完整布局、封面策略、资源卡片与客服；依赖子比读取订单与下载数据，需要在主题升级后检查兼容性。原生模式尽量不接管子比页面，完整布局不与经典模式逐像素一致。

## 多域名与授权身份

- 默认不覆盖 WordPress 数据库中的 `home`、`siteurl`。v3.0.8 **新增一个独立的高风险开关** `domain_legacy_identity_override`，默认关闭；只有站长在“媒体与链接 → 多域名适配”显式选择才恢复旧版 `pre_option_home` 与可选 `pre_option_siteurl`，因此既有站点的旧设置不会自动重启这些授权敏感钩子。
- 保留白名单控制下的前台静态 CSS/JS/font URL 来源适配以及显式启用的常规站内展示链接适配。
- 后台、REST、AJAX、登录 `/wp-login.php`／`/user-sign`、订单和付费下载相关路径无条件排除，不受旧版排除选项状态影响。
- 前台链接转换遇到 `pay-download`、`checkout`、`user-sign`、`wp-admin`、`order` 等路径或查询带 nonce、token、key、action、state 等敏感参数时返回原 URL。
- **注意：**不开启旧版高风险开关时，WordPress 或子比生成的某些绝对 URL 可能仍指向主域名，建议使用白名单展示链接适配。若自行启用旧版动态 `home/siteurl`，即使排除了敏感路径，**任何普通前台请求调用授权校验时仍可能看到别名域名**，子比授权异常不能排除；它不属于默认推荐配置。

## 登录、支付、订单及下载路由强制隔离

v3.1.0 起，无论站长是否启用了全站加载，**沉浸式预加载、页面特效（含输出缓冲注入）和反调试**都不在原生业务路径 `/user-sign`、`/wp-login.php`、`/pay-download`、`/download?post=...`、结算、订单和 `?jlwa_dl=` 票据兑换页面启动。这样避免预加载遮挡登录界面和输出缓冲更改原生 HTML。普通首页和文章仍保留同样的特效，但专用下载页面不再叠加这些全局特效。

多域名显示链接和手工批量域名转换均不得改写上述路由和敏感参数。旧版动态 `home/siteurl` 默认关闭；管理员若手动开启，它仍对普通前台请求有效，**不能保证任意子比授权函数在普通文章页调用时完全不受影响**。真正保证域名身份稳定，应保持该高级选项关闭。

## 两项必要的安全边界

1. `JLWA_Download_Page_Feature::guard_paid_download_page()` 仍会对专用下载页做最小权限判断；未购买时在输出资源内容之前重定向回商品文章。这是原插件保护未购买者的既有功能，不是子比正版主题授权接口。
2. OpenList 私有交付**明确启用时**才注册 `zibpay_download_file_local` 钩子，仅处理站长配置的受保护源站和私有路径。未匹配的普通文件继续由子比处理。已匹配但配置错误的受保护文件必须拒绝，不得退回公开原始下载 URL。文件交付仍需要 Nginx `internal` 与公网源站封锁。

这两项不能在保持安全功能的同时删掉；它们与“完全零触碰子比”存在技术冲突。

## 更新与验收

升级不会主动修改主题源码、数据库已有授权记录、OpenList/Nginx root helper 或公网封锁规则。生产环境继续使用原有插件版本，直到完成以下回归：

1. 在正式主域及附加域打开子比登录、注册、找回密码；确认原生跳转、Cookie 和 AJAX 返回正常。
2. 已购资源分别切换“完整经典模板”和“子比原生兼容皮肤”，在六款视觉方案下检查原有布局、下载按钮、提取码、封面、客服、订单与会员状态；测试手机与桌面。
3. 未登录和已登录但未购买的访客不得打开专用付费资源页，不得获取受保护 OpenList 原始直链。
4. 已购买用户下载受保护文件应保留 X-Accel-Redirect 和最终文件名；未匹配的普通资源应该继续走子比原生流程。
5. 核对主题正版授权在 `blog.jiuliu.org` 与其他入口的表现，特别是 WordPress `home`/`siteurl` 不再随请求域名变化。
6. 不使用真实顾客支付完成测试交易，除非明确具备测试订单与回滚方案；优先选择隔离测试订单／现有已购的只读核对。

测试失败的恢复顺序：先恢复先前的正式插件 ZIP，再恢复原有配置；**不要直接撤除现有 Nginx/OpenList 公网源站保护**。

源代码与自动化测试只能验证行为边界及预期，不能保证任何未公开的 Zibll 授权服务和更新版本永远兼容。
