# 私有交付与 OpenList 公网边界：开发约束

## 通用插件与具体主题依赖

九流 WP 助手是唯一的 WordPress 发布插件；Nginx 根权限工具随同一版本打包。所有域名、目录、端口和容器信息由各站长填写，不在源码及公开文档中固化个人服务器信息。

- **通用能力**：OpenList Nginx 严格公网仅图片防护、回环端口检测、配置预览、受限部署、回滚及只读跨环境配置生成。
- **主题绑定能力**：子比主题提供购买权限判断与下载钩子（`zibpay_download_file_local`、`zibpay_is_paid`）。当前代码**不是** WooCommerce 或所有 WordPress 商城插件的授权适配器；不替代订单服务，不修改子比主题文件。
- 新装站点仅有 `strict_images_only` 策略。没有公开图片目录就拒绝生成安装命令；不允许默认退到只封锁付费目录的弱保护。

## 两条数据路径

**公开图片**：访客 → Cloudflare（可选）→ OpenList 公网域名 Nginx → 仅匹配指定目录 GET/HEAD → 资源响应。

**私有文件**：访客 → WordPress/子比授权 → Nginx `internal` 路径 → 宿主机 `127.0.0.1:<OpenList 端口>` → OpenList 私有文件流。浏览器不能通过公开 OpenList 域名直连原始私有 URL。

配置应对 HTML 首页、OpenList 登录页、`/api/*`、WebDAV、其它 `/d/` 与 `/p/` 目录、畸形编码 URL 一律拒绝公网访问。只按子目录路径白名单放行，不根据文件扩展名或 Referer 声明安全。图片目录里不得存储任何秘密资源。

## 自动部署安全约束

1. 仅支持通过预检的宝塔 Nginx 单 server 虚拟主机；非宝塔使用只读 `render-config` 生成两段 Nginx 配置，由管理员手动布署。
2. 单套 OpenList 若填写多个域名，必须先确认全部属于**同一个** Nginx 配置文件；不同文件必须拒绝自动部署，不能把只保护一个域名当作已保护。
3. OpenList 宿主机端口必须可在 127.0.0.1 连接且 `ss` 确认没有公网监听；Docker 映射不得为 `0.0.0.0` 或通配地址。即使配置了 Cloudflare，直连源站和其它端口也要独立验收。
4. 目标 vhost 根权限归属正确，禁止符号链接和组/其他用户写入。写 root 授权清单之前先校验两份虚拟主机形态、目录、端口、所有域名及现有标记，缺一不可。
5. WordPress PHP 只能借助受限 sudo 调用固定 `status / preview / prepare / confirm / protect / rollback` 操作；安装器只由 root 显式首次安装。不能开放任意 shell/root 功能。
6. 必须按“WordPress 内部代理 → 真实已购下载 → 源站公开访问封锁”的顺序，保留可核验的历史备份。任何 `nginx -t` 失败都要尝试恢复；不得把按钮点击当作购买流程真实验收。
7. 非公开路径不能被 CDN 缓存绕过。公开图片缓存可单独优化，短期私有票据和授权下载必须 `private, no-store`；预览、错误日志和文档不得包含秘密 token。

## 上线与测试

用**全新、空白的模拟站点**测试安装命令：公开图片目录必填、多域名归属一致、多 vhost 拒绝、回环端口拒绝公网监听、部署失败回滚、固定 sudo 操作列表、编码攻击拒绝、真实 Nginx 规则加载。对已购买和未购买用户、完整 ZIP、Range/续传、QQ 登录与支付继续执行人工业务回归。

正式发布遵守主仓库统一十进制版本、中文 Commit/Release 及 SHA256 校验。**更新 WordPress 插件不自动修改或删除旧生产 Nginx 规则**。历史迁移细节仅保留 Git 历史，不作为新安装路径。
