# 私有下载与自动部署：项目内部开发约束

> 这份文档针对九流 WP 助手的后续实现，是**强制边界**，不是一个新插件或独立主题。公开源码、默认设置和教程中不得包含站长的真实域名、服务器 IP、绝对路径、真实文章编号、文件名或存储凭据。

## 唯一开发位置

- **唯一发布与用户界面：九流 WP 助手（wp-assistant）**。新模块进入现有“下载页美化 / 付费资源安全交付”功能域，继续复用原来的设置、更新和 Release 流程。
- **绝不编辑子比主题及其 `zibpay/download.php`、函数或模板源码**，不直接修改其它插件，更不创建一个需要用户单独安装维护的 WordPress 插件。
- 利用子比公开提供的权限接口和 WordPress 钩子：`zibpay_is_paid()`、`zibpay_download_file_local` 等。主题版本不兼容时保守禁用扩展、给管理员明示原因，不通过“热补丁”改主题。
- 不重新实现购买、会员、退款状态判断，不替代订单系统。下载授权以子比当前判断为准。

## OpenList 与域名：一份存储，多种入口

- 一个 OpenList 可以绑定一个或多个域名，直连域名与 CDN 域名仍然指向**同一个服务**。
- 用户界面默认应只展示“OpenList 站点”一个概念；CDN 访问别名作为可选高级项。多个域名指向同一 Nginx vhost 时，只生成/写入**一套**源站保护配置。
- 不能在通用代码中内置特定站点域名或付费目录。运行时由站长在 WordPress 后台本地配置，且只存于其数据库；日志和诊断输出要脱敏，公开 README 和 Release 使用 `example.com` 示例。
- 如被要求清理历史泄露，要明确区分当前主分支和 Git 历史/历史 Release：不擅自强推历史和覆盖不可变 Release。

## v2.6.3 实现与仍需验收的内容

- 插件内已提供受限系统助手、管理向导、自动生成配置、备份、nginx -t、失败回滚与分阶段源站封锁；首次 root 授权仍需要站长在服务器执行一次命令。
- 已增加短期不透明下载票据与自定义下载域名；由于跨域登录 Cookie 不一定共享，票据在有效期内是 Bearer 凭证，并且 CDN 必须绕过缓存。
- 已增授权操作审计、可选保守申请限流和指定文章的匿名旧文件链接 Range 检测。真实买家下载需站长确认；OpenList API、其它公网端口与 CDN 缓存仍必须独立检查。
- 不支持的复杂多 server vhost 不能强行自动改写，用户可以沿用通用手动部署教程。

## 自动部署的持续安全要求

- 首先只读检测：插件读取 WordPress 站点及自身安装路径；站长在后台填写宿主机的 OpenList 本地端口，Docker 容器名称可选。安装脚本由 root 自动匹配 Nginx vhost、确认端口只监听回环及 Docker 映射；异常时不写配置。检测结果不得宣称“自动已保护”。
- 在 WordPress 后台提供“一条安装命令 → 预览修改 → 备份 → 部署 → 检查 → 启用 → 回滚”；后台无需手工输入宝塔 vhost 文件绝对路径，容器名为可选高级项。
- **权限边界：** WordPress `www` 用户通常不能也不该直接写 root 拥有的 Nginx 配置。若需要特权操作，只允许使用与该插件一起发布、由管理员一次性安装/授权的**受限部署入口**。不得给 PHP 用户任意 root/sudo 权限，不得 chmod 777，不得通过公开 Web API 执行通用 shell。
- 对 Nginx 只允许修改站长确认的两个目标网站配置，使用固定模板/路径和确定性注入，拒绝符号链接、意外文件、配置不匹配与重复写入；每次先保存带时间戳和校验值的可恢复备份。
- 操作顺序：写 WordPress `internal` 代理 → `nginx -t` 成功 → reload → 模拟合法购买下载并核对文件 → 写 OpenList 公网目录保护 → `nginx -t` 成功 → reload → 测试匿名旧直链及所有 CDN/源站入口。**任何一步失败，不继续进行下一步**。
- 对 OpenList 匿名/API/缓存旁路、安全签名和目录结构进行检查；不能只因一个 URL 返回 403 就宣布全面安全。已购下载暂未验证时不得先封锁公开源地址。
- 用户可看到上次部署时间、备份文件标识、健康检查结果和“回滚本次配置”。回滚只撤销本插件自己的 Nginx 片段，不破坏站长其他规则。
- 非宝塔、共享主机、没有 Nginx、没有管理员授权的环境要提供清晰的**只读检测和手动教程**，不得声称能一键自动配置。

## /pay-download/：只在插件补审计、节制限流

- 子比原生 Nonce、已购资格及下载次数/会员权限继续有效；绝不修改主题校验源码。
- 通过插件钩子记录有限的下载安全事件（发生时间、文章/文件标识、用户标识、结果、代理脱敏 IP 等），不得记录下载地址中的 token、提取密码、Cookie 或完整私有 URL。
- 限流应是**可配置且默认保守**，按用户和资源组合而非仅 IP 限制；合法大文件续传、多线程下载、移动 IP 变化与付费会员不能被轻易误伤；对过量请求提供可说明原因与恢复窗口。
- 未登录和跨账号拒绝已由子比负责，插件只做必要的补充审计和异常处理，不复制一个新订单权限判断层。
- 先测试游客、A 已购、B 未购、过期订单、免费限额、失败请求和 Range 下载，再评估生产启用。

## 发布与验证

- 版本按统一主版本十进制进位；Commit 和 Release 使用仓库现有的中文主题格式、不可变标签和 CI 流程。
- 所有真实环境内容、测试密码、实际资源 URL 不得写入公开单测/源码/发布备注。安全测试采用 `example.com`、虚构目录和虚构文件名。
- 发布前必须检查 Git diff、配置写入测试、Nginx 语法测试、现有 PHP/JS 回归、备份回滚与源站旁路验收。**未经过线上验收的自动部署，不得显示“已保护”。**


## v3.2.1 公网严格仅图片模式的回环边界

初始 `images_only` 只限制 /d、/p；新版 `strict_images_only` 在 OpenList Nginx vhost 的 server rewrite phase 拒绝所有公网请求，唯一例外是指定图片目录 GET/HEAD。来自回环地址 `127.0.0.1` / `::1` 的完整 OpenList 路径仍可访问；WordPress 付费内部代理直接连接已验证的本机 OpenList 端口。新 root-only CLI `preview-strict-public` / `upgrade-strict-public` / `rollback-strict-public` 只接受锁定的 approved.json 指向的虚拟主机及其源文件 SHA，保留 WordPress vhost 不动。这样既适配生产博客后续增加的独立源站 ACL，也不扩大 WordPress PHP 的 sudo 权限。严格回退只恢复旧的图片目录文件路由白名单，依然禁止付费资源直链，不接受通用全量回滚操作代替。
