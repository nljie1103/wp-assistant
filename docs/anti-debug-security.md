# 九流 WP 助手 · 反调试安全边界与静默探针（v3.0.4）

## 核心边界

- 浏览器页面的 F12/快捷键拦截、窗口尺寸探测、Console 求值、Debugger 耗时探测、遮罩、跳转、刷新和关闭窗口均依赖 JavaScript。访问者可以通过 Chrome 菜单打开 DevTools、从浏览器中禁用 JS、暂停或修改脚本。不能把它们当作权限控制或“杜绝渗透”的保证。
- Chrome 不允许一般网站可靠调用 window.close() 来关闭用户主动打开的标签页；本插件第三级与第四级的“尝试关闭”仅是实验性客户端动作。配置了站内跳转地址后，第三级“跳转指定地址”在 JS 正常运行且探测触发时相对可预期，但仍然不能代替真正的服务器授权。
- 正在公开提供的 HTML、脚本、图片和下载链接都可能被浏览器保存和检查。不要在 JS、HTML、前端隐藏字段或 URL 参数中放置 API 私钥、服务器目录凭证和真正需要保密的内容。

## 静默探针策略

旧版反调试默认在每轮轮询时通过 Console getter 输出 `/jlwa/` 对象；严格模式下还会输出 90 行 Console 性能表格并可能执行 `Function('debugger')()`，导致自动跳转 DevTools Sources。这样的输出会暴露检测逻辑，反而干扰正常用户。

从 v3.0.4 起，探测器页新增两个独立、**默认关闭**的实验开关：
1. **主动 Console 探针（可见输出）**：只有明确开启后才允许执行 Console 求值/Console 性能输出；即使“平衡”或“严格”模式启用了对应检测器，默认也不会打印探针。
2. **Debugger 暂停探针（可能中断）**：只有明确开启后才执行 Debugger 耗时测试。选择“严格模式”不会自动打开此开关。

这两个开关对新安装和此前已经保存严格模式配置的老站点都默认关闭。原有的快捷键、视口差值、页面调试库、失焦辅助、判定分数和四级防御链仍按照保存的设置运行。**第四级“无限 Debugger 循环”是需要单独明确勾选的防御动作，不属于新增 Debugger 耗时探针；如果以前启用了它，仍会生成断点。**

若管理员明确启用主动 Console 探针，仍可能看到测试对象和表格。这是该方法的固有限制，不应宣称它能“静默可靠检测浏览器菜单中的开发者工具”。

## 禁用 JavaScript 时如何保护付费内容

- **文章全文**：只有确实开启「页面特效 → 内容保护 → 正文访问模式 → 限制全文访问」且服务端按角色拒绝输出时，关闭 JS 仍会让服务器返回限制后的正文。默认“公开展示”仅能干扰复制，不能保护已交付的 HTML。
- **登录不等于付费**：该全文模式里 “read / 所有已登录用户” 并不是 Zibll 已购买资格；付费文章必须按 Zibll 的订单/会员权限另行在服务端校验。若要完全保密，不能给无权限访客返回实际全文或可直接访问的媒体 URL。
- **ZIP / OpenList 私有交付**：支付校验应继续由 WordPress PHP 完成，确认后通过 X-Accel-Redirect / Nginx 内部代理交付。匿名访问 /pay-download/ 应拒绝；OpenList /d/ 和 /p/ 的付费路径必须独立封锁。浏览器是否运行 JS，不应改变是否授权的结果。
- **缓存**：付费下载、短期票据、受登录/购买权限影响的正文与 API 返回不得进入公共 CDN 缓存，特别检查其他域名、WebDAV、API、源站 IP 和历史缓存。

## 控制台日志解释

| 日志 | 来源 | 是否是攻击证据 |
|---|---|---|
| `frontend.js ... /jlwa/` | 本插件原有主动 Console getter | 否，来自自身实验性检测 |
| `frontend.js ... Array(90)` | 本插件原有 Console 性能测试 | 否，固定数组是代码刻意生成 |
| `function anonymous() { debugger }` | 开启了 Debugger 耗时探针或第四级循环动作时动态生成 | 否，可能使 DevTools 自动暂停 |
| `[Intervention] Slow network ... fontawesome-webfont.woff` | Chrome 提示 WordPress Zibll 主题字体加载慢 | 否，是加载/字体回退提示 |
| `Zibll Theme...`、数据库查询次数与生成耗时 | 页面主题/其他服务端调试输出；本插件仓库中没有对应的字符串 | 不能据此判断存在入侵 |

URL 上的 `frontend.js?ver=3.0.2` 表示当次页面仍引用旧版本脚本；升级后若仍看到旧参数，需要核对 WordPress 已安装插件版本，清除 WordPress/CDN 页面和静态资源缓存，再以访客无痕窗口重新测试。

## 建议验收步骤

1. 无痕访客打开普通文章，Chrome 菜单开启 DevTools，确认日常模式不再反复输出 `/jlwa/`、90 行表格或主动停到 `debugger`；若曾启用第四级循环应先关闭它。
2. 分别检查停靠式与独立窗口 DevTools。视口变化检测不保证覆盖所有情况，别依赖 DevTools 是否打开来决定服务器是否返回内容。
3. 开启 DevTools 后禁用 JavaScript、重新加载：匿名用户不应看到不应公开的付费全文，也不应能通过真实 ZIP 下载 URL 访问文件。
4. 未购买账号和匿名用户分别直接请求下载接口、OpenList /d/ 与 /p/ 路径、REST/RSS 等，确认服务端确实拒绝。不要只看页面遮罩是否出现。
5. 由真实购买者验证 ZIP 正常完成下载和解压，再检查 Cloudflare/Nginx 缓存是否跨账号复用。

**不要通过默认开启无限 debugger、死循环刷新、无限关闭页签来代替服务器权限检查；这些手段可能误伤访客而且容易绕过。**
