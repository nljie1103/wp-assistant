# 严格反调试与登录兼容性（v3.0.5）

## 为什么以前会误报并影响登录？

- 子比（Zibll）主题的真实登录入口常是 **\`/user-sign?tab=signin\`**。实际站点的 \`/wp-login.php\` 会以 HTTP 302 跳转至 \`/user-sign\`，而原插件只默认排除 \`/wp-login.php\` 与 \`/wp-admin/\`。如果站长开启独立页面保护，严格模式仍可能作用于登录页。
- 登录弹窗在文章页中通过 **\`.signin-loader\`** 打开。打开、关闭弹窗会改变焦点、窗口与滚动状态。原先严格模式的视口/焦点信号可能累计分数，连续的弱信号也能被错误当成“确认检测到开发者工具”。
- 如果站长已启用第三级或第四级的「跳转、循环刷新、持久锁」，一次误报可持续触发跳转或刷新；原会话锁跨站内页面延续，进一步影响登录后的返回页面。
- 浏览器提示 **ERR_TOO_MANY_REDIRECTS** 也可能由 WordPress/Zibll 的 Cookie、登录会话、HTTPS 或 CDN 配置循环造成，不一定来自反调试。对站点的无 Cookie 匿名 HTTP 测试仅观察到 \`/wp-login.php\` → \`/user-sign\` 一次 302，随后 HTTP 200；这一结果不代表有 Cookie 的登录流程一定正常。

## v3.0.5 处理方式

1. **登录地址绝对豁免**：在 PHP 判断脚本是否加载前，识别完整路径段 \`/wp-login.php\`、\`/wp-admin/\`、\`/user-sign\` 与常见 \`/user/login\` 等。不依赖旧的 \`exclude_paths\` 设置，WordPress 子目录安装同样支持。使用完整路径段而不是简单前缀，不会因为豁免 \`/user-sign\` 而把 \`/user-sign-article\` 排除。
2. **登录弹窗期间暂停**：捕获 Zibll 的 \`.signin-loader\` 点击、登录链接及可见的账号密码表单。登录期间立即撤销原来的前端遮罩、交互锁和未执行的防御定时器，清除误报分数。弹窗关闭或提交后再恢复观察，并重新校准视口基线，不把登录期间的焦点变化继续计分。
3. **严格模式需要可信证据**：普通浏览器窗口缩放、仅视口探测、仅焦点变化不会启动防御链。必须有明确开发工具快捷键，或者至少两个不同的新鲜信号且其中一个为较可信探针；原有灵敏度参数、管理员明确选定的防御层、快捷键拦截保留。
4. **防重复跳转**：第三级跳转不可跳到完全相同的 URL，并在浏览器会话内限制 15 秒内重复自动跳转，避免陷入连续自动重定向。
5. **修正历史会话锁**：旧版 \`jlwa_ad_lock_v2\` 会清理；新锁 \`jlwa_ad_lock_v3\` 必须与页面路径匹配。只有真正刷新原页面才能恢复已设置的持久锁；从登录页返回文章属于新的导航，不继承旧锁。

## 保留的能力和安全边界

- F12 及其他快捷键检测、调试库探测、四级防御动作和所有原有 WordPress 管理配置仍按站长选择执行。
- 第三级/第四级的危险跳转、循环刷新与关闭页签功能本来就可误伤访客，而且浏览器端保护可被禁用 JavaScript 绕过；不要将其作为订单/付费资源的访问控制。
- 真正的 ZIP 下载资格仍应由 PHP 中的 Zibll 订单验证及 Nginx/OpenList 私有交付强制校验。该修复未修改服务端订单、插件凭据、Nginx 配置或 CDN 规则。

## 验证

- PHP：常见 WordPress/Zibll 登录路由、子目录、旧保存配置及非登录相似路径的自动测试。
- JavaScript：真实 DOM 事件模拟覆盖严格模式视口误报、弹窗打开期间的保护暂停、已触发防御的撤销、会话锁跨页面、同 URL 禁止跳转和 15 秒重复跳转限制。
- 生产现场：更新后验证从普通文章点击登录、用户名密码登录、第三方登录、登录后返回文章、无痕访客与已登录用户。若仍看到 HTTP \`ERR_TOO_MANY_REDIRECTS\`，需要进一步定位服务器 HTTP 302 Location 链、Cookie 和 CDN 规则；不能只把它归因于 JavaScript。
